# Ribbon Library

## Purpose and boundaries

Open `/studio/ribbon` from Studio's tools or the main dashboard. The catalogue
combines live shared-component specimens, isolated ACM Studio and ACM Account
references, and 56 original ACM icons with 168 SVG variants. The inventory has
73 command/control entries, including conditional links, header controls,
menu actions, text-only fields and state alternatives.

All demonstration changes stay in component memory. The page does not import
product stores, use write ownership, call product APIs or modify accounts,
designs, media, files or backups. It remains usable while another Studio tab
owns editing. Reset Demo and reload restore the fixture. Real navigation,
export and hand-off commands report their intended effect; no files are created.
The small canvas supports selected-object duplication, ordering and undo/redo.
It is a command specimen, not a second drawing editor.

## Architecture and ownership

- `app/studio/ribbon/catalogue-model.ts` is the typed definition and command
  inventory. Its hierarchy drives the structure tree, inspector and renderer.
- `demo-state.ts` contains pure in-memory handlers, fixtures, validity guards
  and current icon/state presentation. UI state is separate from commands.
- `ribbon-preview.tsx` renders the real eight-component `@acm/ribbon` API.
  Tabs are generated by Ribbon. Native fields, the Account split menu and
  compound sliders remain explicit product compositions.
- `ribbon-catalogue.tsx` owns inspection and section navigation. The inspector
  reads dimensions and CSS tokens from its selected rendered element. Choosing
  a conditional command reveals its tab, scenario or menu first.
- The independent sibling `acm-icons` owns editable masters, metadata, generated
  portable assets and the React adapter. Studio does not edit generated paths.

The catalogue shell uses the shared Inter typography baseline. Product specimens
use observed Inter typography, 13px action labels, fixed 114px content panels,
Studio's 16px tabs and Account's 76px main controls. These styles are scoped to
the catalogue; the existing product Ribbons and their icons are unchanged.

## Local setup and verification

From `acm-icons`:

```sh
npm ci
npm run build
npm test
```

From `acm-studio`, after the sibling package exists:

```sh
npm ci
npm run dev
node --experimental-strip-types scripts/generate-ribbon-inventory.mjs --check
node --experimental-strip-types --test tests/ribbon-catalogue.test.mjs
npx tsc --project tsconfig.ribbon.json --noEmit --pretty false
npm run typecheck
npm run lint
npm test
git diff --check
```

The test command includes the production build. Do not run an extra identical
build. The focused TypeScript configuration resolves the consumer's React types
for sibling packages without altering the shared Ribbon repository. The broad
typecheck currently has pre-existing Design Editor event/nullability errors and
missing React types in the Ribbon checkout; report that limitation separately.

From `_Projects`, run
`node workspace-governance/scripts/audit-project-docs.mjs`.

Run `node --experimental-strip-types scripts/generate-ribbon-inventory.mjs` from
Studio to update [the generated command inventory](ribbon-command-inventory.md).
Test coverage checks complete icon/state coverage, preserved shape and zoom
options, strict SVG syntax, deterministic generation, accessibility rendering,
unique IDs across real Ribbon instances, exclusive tool state, selection/history
reconciliation, filtered table selection, scoped ranges and reset. Commands run
against frozen fixtures with throwing network/storage/DOM-access spies.

## Browser verification and adoption

The golden reference set has been visually reviewed at 16/24/32px on light and
dark surfaces. Small table-cell and row symbols remain a particular optical
review point. The current full library is available for continued review in
Icons; adoption by working product Ribbons remains a subsequent decision.

Required browser checks include real hover/focus, tabs and hidden panels,
selection and icon state, menus with Escape/close focus restoration, sliders,
search/filter/reset, conditional controls, responsive layout and 200% browser
zoom. Use `data-region` markers to identify preview boundaries.

Main's initial browser pass confirmed desktop/tablet/phone reflow, contained wide
previews, slider keyboard changes, menu focus restoration, synthetic search and
loading, fixed panel height, and navigation while another tab owned editing.
True 200% browser zoom was unavailable in the provided browser controls; viewport
reflow is separate evidence and must not be presented as a zoom pass.
